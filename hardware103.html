Hardware 103: Reverse Engineering the Action Thermal Printer

Reverse Engineering Software / Firmware Electronics & Circuits

Overview & Objectives

During the Hardware 103 session, my team of three decided to dive into hardware reverse engineering. We selected a budget pocket thermal label printer from Action (Fichero series) to analyze how it receives print commands and to see if we could control it independently.

Why Reverse Engineer a Budget Printer?

Cheap consumer smart hardware often comes with significant drawbacks:

  • Proprietary Apps: Off-the-shelf apps frequently require account creation, location permissions, and show unwanted ads just to print a simple text label.
  • Vendor Lock-in: If the manufacturer shuts down their cloud server or stops updating the app, the physical device becomes e-waste.
  • Customization: Reverse engineering the communication protocol allows developers to print automatically from custom scripts, microcontrollers, or web apps without human intervention.

Investigation & Technical Findings

Instead of building an exploit entirely from scratch, we started by researching existing open-source work surrounding these chipset families (such as BLE GATT services or serial packet structures common in thermal receipt printers).

We located an open-source GitHub repository detailing the custom Bluetooth packet headers used by the device. By leveraging a Web Bluetooth API script, we succeeded in establishing a direct connection to the printer from a browser interface—bypassing the official smartphone application entirely.

Key Learnings

  • Packet Structure: Understanding bitmap conversion and line-by-line rasterization for thermal printheads.
  • Web Bluetooth (BLE): How modern browsers communicate with low-energy embedded peripherals.
  • Hardware Sovereignty: Unlocking locked-down commercial hardware for open open-source control.

Hardware 102: Prototyping an LED Slot Machine

Basics Microcontrollers Software / Firmware

Concept & Concepting

Building on the basics learned in the first lesson, I set out to build a mini LED slot machine game using the Raspberry Pi Pico kit. Inspired by traditional fruit machines (where you pull a lever and hope to align three matching symbols), my goal was to simulate the mechanic using three LEDs as the "reels" and a push button as the "lever."

Game Rules & Planned Logic

  • Idle State: Pressing a push button initiates the game cycle.
  • Spinning Phase: The three LEDs cycle rapidly in a sequence to simulate spinning reels.
  • Stopping & Win Check: The LEDs stop sequentially on a random pattern. If all 3 LEDs end up turned ON, the player wins (triggering a victory flash); otherwise, it signals a loss.

Challenges & Current Blockers

While the circuit wiring (connecting 3 LEDs with resistors to GPIO pins and wiring a button) was straightforward, implementing the game loop in MicroPython proved tricky:

  • Non-blocking timing: Using standard time.sleep() pauses execution completely, making it hard to register button presses or stagger the stopping of each individual LED cleanly.
  • Randomization: Implementing pseudo-random state generation in MicroPython required logic I wasn't fully familiar with yet.

Key Takeaways & Next Attempt

Although I didn't get the game working completely before the end of the bootcamp session, the attempt forced me to think about microcontroller state machines and timing loops instead of just turning pins on and off.

My next step will be breaking down the logic into smaller chunks: getting single-LED timing working first before combining all three into the main game loop.
